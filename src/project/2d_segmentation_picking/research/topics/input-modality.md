# 입력 모달리티: [RGB] vs [RGB-D] vs [RGB-D-N]

> 작성일: 2026-10-29 · 담당: input-modality 조사 에이전트
> 범위: "세그멘터가 무엇을 보는가"(컬러 / 깊이 / 법선)와 융합 방식. 검출기·분할기 자체의 비교는
> `detectors.md`, `segmenters.md`가 담당한다.
> 표기: **확인** = 출처(URL 또는 레포 파일 경로) 있음, **(추론)** = 근거는 있으나 직접 측정·확인 못함.
> 이 문서는 조사만 했다. 모델 설치·실행은 하지 않았다.

## 0. 요약

| 시나리오 | [RGB] | [RGB-D] | [RGB-D-N] | 한 줄 판단 |
|---|---|---|---|---|
| [BOX] 높이 같은 박스 밀착 | 기본 | 이득 작음 | 이득 작음~중간 | 경계는 RGB(테이프·인쇄·틈 그림자)가 결정한다. 깊이·법선은 **층 분리·높이 다른 박스·모서리 R** 정도에만 기여 (추론, Box-IS +0.4 AP 근거) |
| [UNK] 빈 속 파우치 클러터 | 기본 | **후처리 융합으로 이미 사용 중**(m1) | 법선을 **주 입력으로 쓰면 손해**, 보조 신호로는 이득 가능 | 파우치는 평평·밀착이라 깊이/법선 경계가 없음 (확인: 레포 노말맵 실험) |
| [ONE]/[FEW] 강체 소비재 | 기본 | 이득 중간 | **이득 큼**(곡면·같은 색 밀착) | 원통·박스는 법선 꺾임이 뚜렷 (확인: scene03에서 RGB m1이 평면 병합으로 합친 원통 2개를 노말맵 m1은 분리 — 4.2장) |
| [ONE]/[FEW] 무늬 없는·반사 산업 부품 | 약함(무늬 없음) | 이득 크지만 **결측·노이즈 위험** | 법선 노이즈 더 큼 | 깊이 신뢰도(SNR) 마스킹이 전제 (확인: 2002.03501) |
| [ONE]/[FEW] 연성 파우치 | 기본 | 이득 작음 | 이득 작음 | [UNK]와 같은 이유 (추론) |

**결론(추론)**: 이 프로젝트에서 모달리티 문제의 정답은 "어떤 채널을 모델에 넣느냐"보다
**"RGB로 제안하고 깊이·법선으로 쪼개고 합치는 후처리 융합"** 쪽이다. 입력 단계에서 RGB를
법선으로 **대체**하는 것은 장면 유형에 따라 이득과 손해가 뒤바뀐다(4장). RGB-D 전용
UOIS 모델(UCN, MSMFormer, UOAIS-Net 등)은 라이선스·환경·도메인 3중 문제로 추천하기 어렵다(3장).

## 1. 레포의 현재 상태 (확인)

| 항목 | 내용 | 근거 |
|---|---|---|
| 법선 로드 | `point_cloud.copy_data("normals")` → (H,W,3) float [-1,1], NaN=무효 | `core/loader.py:35` |
| 노말맵 인코딩 | 채널당 `0.5*(1-n)*255`, 무효 픽셀 검정 (zivid-python-samples `convert_zdf_file_dir.py` `_create_normal_map`과 동일) | `core/viz.py:91` `normals_to_rgb` |
| m1의 깊이 사용 | 최상층 밴드 게이팅(bin frame 높이) + AMG 포인트를 밴드 내부에만 배치 + **마스크별 평면 피팅(XYZ 트리밍 PCA) → 인접 마스크 normal 각도차·offset 병합** | `PLAN.md` 5·11장, `core/plane.py`, `config/m1_sam2.yaml` `merge.normal_deg: 8` |
| 주의 | m1 병합이 쓰는 normal은 **Zivid 픽셀 법선이 아니라 XYZ로 마스크마다 PCA한 평면 법선**이다. 즉 현재 m1은 엄밀히 [RGB-D] 후처리 융합이고, Zivid `normals` 채널은 노말맵 실험에서만 쓰였다 | `core/plane.py:121-158` |
| m2의 깊이 사용 | 최상층 게이팅 + 중복 제거·평면 지표만. 병합은 의도적으로 끔 | `PLAN.md` 11장 |
| 폐기 이력 | 순수 기하(RANSAC+DBSCAN)는 밀착 파우치에 깊이 불연속이 없어 폐기. UOIS 계열은 torch 1.x/Python 3.8/CUDA 확장 빌드로 단일 환경 불가 | `PLAN.md` 5장 |

즉 [RGB-D]는 **이미 후처리 융합 형태로 기준선(m1)에 들어가 있다.** 이 조사의 질문은
"그 이상(입력·특징 단계 융합, 픽셀 법선)이 이득인가"이다.

## 2. 융합 방식 분류

| 방식 | 설명 | 예 | 장점 | 단점 |
|---|---|---|---|---|
| **입력 단계 (A1) 채널 추가** | RGB에 D(·N)를 4~7채널로 붙여 학습 | Mask R-CNN RGB-D early, UCN "early" | 구현 단순 | 사전학습 RGB 가중치와 안 맞음 → **학습 필수**. UCN 실험에서 early가 late(add)보다 낮음 (확인, 3.2장) |
| **입력 단계 (A2) 3채널 렌더링 후 RGB 모델에 투입** | 깊이를 컬러맵으로, 법선을 노말맵으로 바꿔 SAM 등에 그대로 넣음 | SAD(Segment Any RGBD), ZISVFM의 "SAM on colorized depth", **이 레포의 노말맵 실험** | 학습 0, 기존 파이프라인 재사용 | 텍스처 정보 손실, 동일 평면 물체 병합, 텍스트 검출기(m2)는 도메인 붕괴 |
| **입력 단계 (A3) 대체가 아닌 병렬** | RGB와 렌더링 깊이/노말맵에 각각 SAM 실행 → 마스크 합집합·투표 | ZISVFM(깊이로 제안, RGB로 정밀 분할) | 학습 0, 두 신호의 장점 결합 가능 | 추론 시간 ×2, 병합 규칙 설계 필요 (추론) |
| **특징 단계** | RGB·D 별도 인코더 → 특징 덧셈/어텐션 융합 | UCN "add"(late), MSMFormer RGB-D, IAM, DA-Fusion | 문헌상 최고 성능대 | 학습 필수, 공개 가중치는 탁상(tabletop) 합성 데이터 기준 |
| **후처리 단계** | RGB 마스크를 깊이 불연속·법선 변화로 **분할(split)** 또는 **병합(merge)**·기각 | **m1 평면 병합**, UOIS-Net-3D(깊이로 분할 → RGB로 정련, 역방향) | 학습 0, 모델 교체와 무관하게 재사용, 결정적 | 깊이 경계가 없는 경우(파우치)는 아무것도 못 함 |

## 3. 문헌 근거

### 3.1 깊이가 RGB보다 강하다는 근거 — 단, 탁상 장면·합성 학습 조건 (확인)

**UCN (Xiang et al., CoRL 2020)** 입력 ablation, OCID / OSD, Overlap F / Boundary F, zoom-in 정련 전
([ar5iv 2007.15157](https://ar5iv.labs.arxiv.org/html/2007.15157)):

| 입력 | OCID | OSD |
|---|---|---|
| RGB | 59.4 / 36.5 | 63.3 / 39.1 |
| Depth | 86.4 / 75.6 | 81.0 / 50.9 |
| RGB-D early(채널 연결) | 82.8 / 67.2 | 79.2 / 53.0 |
| **RGB-D add(특징 덧셈, late)** | **88.5 / 78.8** | **86.2 / 67.1** |
| RGB-D concat(특징 연결) | 82.9 / 68.5 | 79.7 / 48.8 |

같은 논문의 Mask R-CNN도 RGB 67.2 → Depth 84.7(OCID Overlap F). **입력 단계 연결(early)은 깊이 단독보다
낮다** — 채널 붙이기만으로는 이득이 보장되지 않는다.

**UOIS-Net-3D (Xie et al., T-RO 2021)** ([ar5iv 2007.08073](https://ar5iv.labs.arxiv.org/html/2007.08073)):
Mask R-CNN RGB 36.6 → Depth 79.9 → RGB-D 78.0 (OCID Overlap F). 저자들은 "깊이가 일반화를 크게 올리지만,
깊이만으로는 날카로운 경계가 불가능하다 → RGB로 정련"이라고 쓴다. 즉 **깊이로 분리, RGB로 경계**라는 역할 분담.

**ZISVFM (2025, arXiv 2502.03266)** — SAM ViT-H에 RGB vs 컬러맵 깊이를 넣은 기준선
([arXiv HTML](https://arxiv.org/html/2502.03266)):

| SAM 입력 | OCID Overlap F / Boundary F / F@.75 | OSD |
|---|---|---|
| RGB | 40.0 / 36.7 / 63.7 | 43.3 / 42.7 / 70.6 |
| 컬러맵 깊이 | 84.4 / 78.5 / 83.6 | 60.0 / 41.3 / 63.6 |
| ZISVFM(깊이 제안 + DINOv2 필터 + RGB 프롬프트 분할) | 89.2 / 83.5 / 87.0 | 78.1 / 60.0 / 66.0 |

OSD에서는 깊이가 Overlap F만 올리고 Boundary F·F@.75는 RGB와 같거나 낮다.

**SAD — Segment Any RGBD** ([README](https://raw.githubusercontent.com/jun-cen/SegmentAnyRGBD/main/README.md)):
"렌더링 깊이 이미지가 SAM의 과분할을 완화한다. 다만 가까운 두 물체가 깊이에서 한 마스크로 합쳐질 때는
RGB가 텍스처로 분리한다." — 정량 없음, 정성 서술. 이 레포의 노말맵 실험 결과와 정확히 같은 양상이다(4장).

**왜 이 수치를 그대로 믿으면 안 되나 (추론)**:
1. OCID/OSD는 **탁자 위에 물체가 흩어진** 장면이라 물체 사이에 깊이 불연속이 거의 항상 있다. 밀착 파우치·같은 높이 박스는 정반대 조건이다.
2. RGB 수치가 낮은 것은 상당 부분 **비사실적 합성 RGB로 학습한 sim-to-real 격차** 때문이다(UOIS-Net-3D 저자 서술, 확인). SAM 세대 RGB 모델에서는 격차가 줄어든다 → 3.2장.
3. "SAM(RGB) 40.0"은 AMG 전체 이미지 적용 시 텍스처 과분할이 큰 탓. m1은 이미 최상층 밴드·평면 병합으로 이 약점을 줄였다.

### 3.2 RGB 기반 모델이 따라잡았다는 근거 (확인)

**UOIS-SAM (Cao et al., arXiv 2409.15481, ICRA 2025 제출)** — **RGB만** 사용, SAM ViT-L + 히트맵 프롬프트 생성기
([arXiv HTML](https://arxiv.org/html/2409.15481v1)): OCID Overlap F 79.9 / OSD 78.9로, 같은 표의 MSMFormer(70.5/67.9),
UOAIS-Net(67.9/83.8)보다 OCID에서 높다. 그런데 UOAIS-Net 67.9/83.8은 UOAIS 논문 표의 **RGB 입력** 수치와
일치한다([ar5iv 2109.11103](https://ar5iv.labs.arxiv.org/html/2109.11103), 확인) → UOIS-SAM은 **RGB 버전끼리** 비교한 것으로 보인다(추론).
같은 모델의 깊이/RGB-D 버전(OCID: UOAIS Depth 89.8, MSMFormer+ RGB-D 91.5)은 여전히 UOIS-SAM(79.9)보다 높다.
즉 "SAM으로 RGB 격차가 줄었지만 탁상 장면에서는 깊이가 아직 앞선다"가 정확한 요약이다. 저자는 깊이 추가를 향후 과제로 남겼다.

**같은 모델 내 입력 ablation (확인)**:

| 모델 | 입력 | OCID Overlap / Boundary F | OSD Overlap / Boundary F | 출처 |
|---|---|---|---|---|
| MSMFormer (TOD 학습) | RGB | 67.7 / 55.8 | 63.6 / 47.0 | [ar5iv 2211.11679](https://ar5iv.labs.arxiv.org/html/2211.11679) |
| | RGB-D | 88.5 / 83.0 | 82.8 / 60.6 | |
| UOAIS-Net (UOAIS-Sim 학습) | RGB | 67.9 / 62.3 | 83.8 / 72.1 | [ar5iv 2109.11103](https://ar5iv.labs.arxiv.org/html/2109.11103) (표 열 정렬은 추출 결과 기준) |
| | Depth | 89.8 / 84.7 | 85.5 / 66.9 | |
| | RGB-D | 71.9 / 68.8 | 85.2 / 73.0 | |

UOAIS에서 **RGB-D가 Depth보다 OCID에서 크게 낮다** — 저자는 OCID의 복잡한 텍스처 배경이 RGB-D 모델의 전경 분할을 해쳤다고 설명. "채널을 더 넣으면 좋아진다"는 보장이 없다는 두 번째 근거(첫째는 UCN early fusion). 코드는 "출판 시 공개" 상태로 레포를 찾지 못했다.

**"Bin-picking of novel objects ...: RGB matters" (IRC 2023, [arXiv 2312.16741](https://arxiv.org/abs/2312.16741))**:
노이즈 많은 깊이·투명 물체가 있는 빈 피킹에서 **합성 RGB 학습**이 깊이 기반 선행 연구보다 낫다고 주장.

### 3.3 박스·산업 부품에서 깊이의 이득 (확인)

| 연구 | 조건 | RGB | RGB-D | 해석 |
|---|---|---|---|---|
| IAM + Box-IS ([arXiv 2501.01685](https://arxiv.org/html/2501.01685v1)) | 박스 1클래스, 543장, RealSense D455(스테레오 깊이 재계산), SOLQ | 83.3 AP | 83.7 AP | **박스에서는 깊이 이득 +0.4로 미미**. 소형 물체 AP는 오히려 RGB가 높음(7.9 vs 7.2) |
| Segmenting Unseen Industrial Components ([ar5iv 2002.03501](https://ar5iv.labs.arxiv.org/html/2002.03501)) | 금속 부품 클러터, RealSense D415, 합성 학습 | 67.1 AP50 | 69.0 AP50 (신뢰도 맵 융합) | 단순 early fusion은 RGB보다 **나빴다**. 반사 금속에서 깊이 결측·노이즈 때문에 **깊이 신뢰도 가중**이 핵심 |
| SupeRGB-D ([ar5iv 2212.11922](https://ar5iv.labs.arxiv.org/html/2212.11922)) | 탁상 클러터, 슈퍼픽셀 병합 | Overlap F 69.5 / Boundary F 61.9 | RGB+D 76.3 / 65.1, **RGB+D+N 76.5 / 66.8** | **법선은 Overlap에 거의 영향 없고 경계에만 소폭 도움**(저자 서술) — 법선 채널 효과를 분리한 거의 유일한 ablation |
| 디팔레타이징 문헌 (MDPI Sensors 24(5):1473 등, [링크](https://www.mdpi.com/1424-8220/24/5/1473)) | 택배 박스 | — | 깊이 Canny 경계 + YOLACT RGB 경계 중첩 | 깊이를 **경계 후처리**로 씀. 같은 높이 밀착 박스를 직접 다룬 논문은 찾지 못함 |

**같은 높이·밀착·같은 무늬 박스(동일 평면)**: 깊이 불연속도 법선 변화도 없다. 경계 정보는 박스 사이의
**미세한 틈(수 mm)과 그 그림자, 모서리 라운드, 테이프** 뿐이다. Zivid 해상도·점 간격(작업거리에 따라 대략
0.3~1mm/px 수준, 추론)이면 모서리 R은 법선맵에서 선으로 보일 가능성이 있지만, 이를 정량 확인한 자료는 찾지 못했다.

**평평한 파우치 밀착**: 깊이 차 = 파우치 두께(수 mm 이하)와 겹침 단차뿐. 법선은 주름·말림에서만 변한다 → 4장 실험이 직접 증거.

### 3.4 2025-2026 동향 (확인, 상세 미확인)

- **ZISVFM** (2025): 위 표. 학습 0, SAM(컬러맵 깊이) + DINOv2 ViT-B/14 + SAM(RGB) → 카드 `candidates/zisvfm.md`.
- **DA-Fusion** ([arXiv 2607.17754](https://arxiv.org/abs/2607.17754), ICRA 2025 게재 표기): deformable attention RGB-D 융합, 빈 피킹 탑다운 클러터 데이터셋 OCBD 제안. 수치·코드 미확인.
- **SPDA-SAM** ([arXiv 2602.06335](https://arxiv.org/html/2602.06335v1)): 깊이 인지 self-prompt SAM. UOIS 벤치마크 미평가.
- **CAD-Prompted SAM3** ([arXiv 2602.20551](https://arxiv.org/html/2602.20551)): 산업 부품 기하 조건부 분할 — [ONE]/[FEW] 산업 부품용으로 별도 조사 가치 (`segmenters.md` 영역).
- 요약(추론): 2025년 이후 흐름은 "RGB-D 전용 네트워크를 처음부터 학습"보다 **SAM 계열 RGB 기반 + 깊이를 프롬프트/필터/후처리로 주입**하는 방향이다.

## 4. 이 레포의 노말맵 실험 해석 (`scripts/run_normal_experiment.py`)

|---|---|---|---|---|---|

**image_test_01~03은 `data/eval/` GT(장면 01~12)에 포함되지 않는다** → 이 실험은 정답 대비 recall로 채점할 수 없다. 후보 수 차이는 품질 차이가 아니다.
타이밍도 비교 불가: 스크립트가 m1·m2를 **한 프로세스에 순차 로드**해 AGENTS.md 측정 규칙(방법당 독립 프로세스)을 어긴다(확인, 스크립트 99-117행). scene03 m1 노말 warm 4.7s는 이 영향으로 보인다(추론).

### 4.2 오버레이 육안 확인 (확인: PNG 직접 열람, 해석은 추론)

- **image_test_01 (파우치)**: 노말맵 m1은 바닥에 평평하게 누운 파우치(김치·만두 봉지 등)를 **거의 다 놓쳤고**, 왼쪽 빈 벽면을 큰 마스크(rank 0)로 잡았다(`tilt` 기각이 `null`이라 통과). 반면 큰 인쇄 파우치는 텍스처 과분할 없이 한 마스크로 나왔다. m2(Grounding DINO)는 노말맵에서 "pouch/box" 어휘가 거의 작동하지 않아 4개만 남았다 — 텍스트 검출기는 노말맵 도메인을 모른다.
- **image_test_02 (강체)**: 박스·원통이 형상 단위로 깔끔하게 분리되고 라벨 인쇄로 인한 조각이 줄었다. 대신 일부 물체 누락, 큰 파우치는 겹친 마스크 2개로 나왔다.
- **image_test_03 (희소)**: 나란히 누운 남색 원통(보온병) 2개를 RGB m1은 **한 후보(rank 2, area 85,628px, `merged_from: 3`)**로 냈고, 노말맵 m1은 두 후보(각 약 42,700px, 병합 없음)로 냈다(확인: 두 report JSON의 `topk`). 원통 밑 노란 박스도 노말맵 쪽에서만 별도 마스크.
  - **주의 — 원인은 RGB가 아니라 m1의 평면 병합일 가능성이 크다.** RGB 쪽 마스크는 원래 3개였고 `merge`(normal 8°, offset 3mm)가 이를 합쳤다. 같은 높이·같은 방향으로 나란히 놓인 두 물체는 평면 피팅 결과가 거의 같아 **병합 규칙이 서로 다른 물체를 합친다**(추론). `PLAN.md` 11장의 "잘못 병합된 사례 없음"은 scene01 육안 기준이었고, 이 사례는 그 반례로 보인다. **[BOX] 같은 높이 밀착 박스에서 정확히 같은 위험이 있다** → 병합 조건에 "두 마스크 사이 경계에 깊이/법선/RGB 엣지가 없을 것"을 추가해야 한다(추론).

### 4.3 해석

- 가설("깊이는 이어져도 법선은 꺾인다")은 **강체 곡면·모서리에서는 맞고, 평평한 파우치에서는 틀렸다.**
- 노말맵 **대체**는 m1에 대해 SAD 논문과 같은 트레이드오프(과분할↓, 동일 평면 병합↑·평평한 물체 누락↑)를 보였고, m2에는 일방적으로 해롭다.
- 노말맵 인코딩은 **카메라 좌표계 법선**이다. 한 장면 안의 상대 대비에는 문제없지만, 카메라 설치 자세가 바뀌면 같은 빈 바닥·벽의 색이 달라진다 → 장면·설치 간 일관성을 원하면 bin frame으로 회전한 법선을 인코딩해야 한다(추론, `PLAN.md` 4장 원칙의 연장). Zivid 문서상 "법선만 변환은 불가, 포인트클라우드를 먼저 변환 후 법선 계산"이다([Zivid KB Normals](https://support.zivid.com/en/latest/academy/applications/normals.html), 확인) — 단 numpy에서 회전 행렬을 곱하는 것은 가능하다(추론).
- 다음 실험은 **대체가 아니라 병렬**(RGB 마스크 ∪ 노말맵 마스크 → 중복 제거·평면 병합)이 맞다(추론). 노말맵에서만 나온 마스크가 RGB 마스크 하나를 둘로 가르는 경우(scene03 원통)를 **split 근거**로 쓰는 형태.

## 5. 시나리오별 기대 이득 (추론 중심)

### [BOX] 팔레트 박스 1/2/3종
- [RGB]: 테이프·인쇄·틈 그림자가 주 경계. 1종 동일 박스 밀착이 최난도.
- **경고**: m1식 평면 병합(normal 각도차 + offset)은 같은 높이 박스를 **전부 한 덩어리로 합칠 수 있다**(4.2장 scene03 원통 사례). [BOX]에서는 병합을 끄거나 경계 엣지 검사를 붙여야 한다(추론).
- [RGB-D]: **층 분리**(최상층 게이팅은 m1에서 이미 확인된 효과), 높이가 다른 혼합 팔레트(2/3종)에서 경계 확정, 평면 피팅으로 마스크가 두 박스를 걸쳤는지 검사(`inlier_ratio`, `PLAN.md` 11장). 같은 높이 밀착에서는 이득 거의 없음(Box-IS +0.4 AP, 확인).
- [RGB-D-N]: 박스 모서리 라운드·약간의 기울기 차이가 법선맵에 선으로 나타나면 분할 근거가 된다. 확인된 자료 없음 → **3단계 실험에서 직접 측정할 1순위 항목.**
- 핵심 후처리: 박스는 직사각형이라 **평면 + 직사각형 피팅**(크기 사전정보)으로 과병합 마스크를 쪼갤 수 있다 — 모달리티보다 형상 사전정보가 더 효과적일 가능성(추론).

### [UNK] 빈 속 파우치 클러터
- [RGB-D]: m1 방식(밴드 게이팅 + 평면 병합)이 이미 최선의 형태. benchmark에서 m1 과분할 물체 5개(12장면, `data/eval/benchmark_results.json`, 확인 — 6641c95 이전 산출물일 수 있음).
- [RGB-D-N]: 주 입력으로는 손해(4장). 보조로는 "마스크 내부 법선 분산이 크면 두 물체 걸침" 기각 지표 정도.
- RGB-D 학습형 UOIS 모델: 학습 데이터(탁상 합성)와 도메인 차가 커서 이득 불확실.

### [ONE]/[FEW]
| 제품 유형 | [RGB-D] | [RGB-D-N] | 비고 |
|---|---|---|---|
| 강체 소비재(병·캔·소형 박스) | 중간 | **큼** | 같은 제품이 나란히 붙으면 RGB는 합치기 쉬움(scene03 원통). 법선 꺾임이 분리 근거 |
| 산업 부품(무늬 없음·반사) | 큼(RGB에 경계 정보가 적음) | 중간 | 반사면 깊이 결측·노이즈 → **SNR 마스크로 신뢰도 가중** 필수(2002.03501 교훈). 법선은 깊이 미분이라 노이즈 증폭 |
| 연성 파우치 | 작음 | 작음 | [UNK]와 동일. 학습형 RGB 모델([ONE]/[FEW]는 학습 데이터가 있음)이 더 효과적일 것 |

[ONE]/[FEW]는 학습 데이터를 만들 수 있으므로 **RGB-D 4채널 학습형 모델**(YOLO-seg/Mask R-CNN 계열에 깊이 채널 추가)도 선택지가 된다. 단 UCN 결과처럼 early fusion이 항상 이기지는 않으므로 RGB 학습 모델 대비 A/B가 필요하다.

## 7. 3단계 공정 비교 실험 설계 (제안)

목표: **같은 세그멘터, 같은 GT, 입력만 다르게.** 모달리티 효과를 모델 효과와 분리한다.

### 7.1 고정할 것
- 세그멘터: SAM2(현재 m1 체크포인트·AMG 설정)와, 2단계에서 선정될 최종 세그멘터 1종. 각 모달리티 조건에서 **가중치·프롬프트 수·임계값 동일**.
- ROI·최상층 게이팅·bin frame: 모든 조건에서 동일한 XYZ 기반(현재처럼). `bin_frame_*.json` 재생성 금지(AGENTS.md).
- 측정: 방법·조건당 **독립 프로세스**, cold 1회 버림, warm 5회 중앙값. 추론/후처리/인코딩 시간을 분리 기록.

### 7.2 비교 조건 (같은 SAM2, 같은 후처리 코드)

| ID | 세그멘터 입력 | 후처리 | 의미 |
|---|---|---|---|
| C0 | RGB | 없음(병합·기각 off) | 순수 [RGB] |
| C1 | RGB | 평면 병합(현재 m1) | [RGB-D] 후처리 융합 = 기준선 |
| C2 | RGB | 평면 병합 + **깊이 불연속/법선 경계 split** | [RGB-D-N] 후처리 융합 |
| C3 | 노말맵 | 평면 병합 | 대체 (기존 실험 재현, bin frame 법선으로 인코딩) |
| C4 | 컬러맵 깊이(bin frame 높이) | 평면 병합 | SAD/ZISVFM 방식 대체 |
| C5 | RGB ∪ 노말맵 (병렬 AMG) | 중복 제거 + 평면 병합 | [RGB-D-N] 입력 병렬 융합 |
| C6 (선택) | RGB + D 융합 학습 모델 | — | [ONE]/[FEW]에서만, 같은 학습 세트로 RGB-only 모델과 A/B |

C3/C4에는 m2(Grounding DINO)를 쓰지 않는다 — 텍스트 검출기의 도메인 붕괴가 모달리티 효과를 가린다(4장 확인).

### 7.3 GT·지표
- [UNK]: 기존 `data/eval/` 12장면, `run_benchmark.py`와 같은 지표(recall@IoU0.5, 과분할 물체 수, 미매칭 후보 수) + **과병합 물체 수**(후보 1개가 GT 2개 이상과 IoU≥0.3) 추가 — 깊이·법선 대체의 주된 실패 모드가 과병합이기 때문.
- **GT 편향 주의(확인)**: 현재 GT는 `gen_gt_fragments.py`로 **RGB SAM2 조각을 사람이 묶어** 만들었다. 경계가 RGB 마스크에서 나오므로 RGB 조건에 유리할 수 있다. 완화: (1) IoU 0.5 기준이라 영향은 제한적일 수 있음(추론), (2) [BOX]/[ONE]/[FEW] 새 GT는 노말맵·RGB 조각을 **둘 다** 후보로 제시해 묶거나 폴리곤으로 직접 그린다.
- [BOX]: 박스 1/2/3종 × (같은 높이 밀착 / 높이 혼합) 2조건 이상. 박스는 정답 마스크가 직사각형이라 라벨링이 쉽다.
- [ONE]/[FEW]: 강체 / 무늬 없는·반사 / 파우치 각각 별도 집계. 반사 부품 장면에서는 **NaN 비율**도 함께 기록해 모달리티 효과와 깊이 품질을 연결한다.
- 각 장면의 하위 그룹 태그: "밀착 동일 평면", "곡면 밀착", "높이 차" — 어떤 기하 조건에서 어느 모달리티가 이기는지 분해.

### 7.4 판정
- C1 대비 recall·과분할·과병합의 **장면 단위 짝비교**(같은 장면에서 차이)로 본다. 12장면이면 통계적 유의성은 약하므로 부호 일관성(몇 장면에서 이겼나)을 함께 보고한다.
- 속도 예산(0.5s 목표, 1s 한도) 초과 조건은 품질이 좋아도 "조건부 채택"으로 분류.

## 8. 가장 큰 불확실성

1. **[BOX] 같은 높이 밀착 박스에서 Zivid 법선이 모서리 R·틈을 선으로 보여주는가** — 문헌·레포 모두 증거 없음. 1회 캡처로 노말맵만 봐도 바로 판단 가능.
2. **m1 평면 병합의 과병합 위험** — scene03에서 나란히 놓인 원통 2개가 `merged_from: 3` 한 후보로 나왔다(4.2장). 현재 벤치마크 지표에 "과병합"이 없어 이 실패가 recall에 잘 안 드러난다. [BOX]로 가면 치명적일 수 있다.
3. 노말맵 실험 장면(image_test_01~03)에 GT가 없어 **노말맵 효과가 정량 미확인**. 육안 판단뿐.
4. UOIS 벤치마크(OCID/OSD)의 "깊이 압승"이 빈 탑다운 밀착 장면에 얼마나 전이되는가.
5. 반사 산업 부품에서 Zivid 깊이 결측률 — 장면·설정(Omni/Stripe 엔진 등)에 따라 크게 다를 것(추론).
6. 공개 RGB-D UOIS 모델 대부분이 비상업 라이선스 또는 비상업 가중치에 의존 → 상용 경로는 MIT인 UOIS-Net-3D 정도뿐이며, 그것도 성능은 최신 대비 낮다.
