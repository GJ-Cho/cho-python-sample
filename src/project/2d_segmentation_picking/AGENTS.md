# AGENTS.md — 2D Segmentation Picking Demo

> 상위 `cho-python-sample/AGENTS.md`(Zivid 규칙)와 전역 지침을 상속합니다. 여기엔 이 폴더 고유 규칙만 씁니다.

Zivid 카메라 + UR3e 로봇으로 **언논 오브젝트(unknown object)를 2D 세그멘테이션 기반으로 피킹하는 데모** 프로젝트다.

## 시작 전 반드시 할 일

1. **`PLAN.md`를 먼저 읽는다.** 설계 결정과 근거, 폐기된 대안, 튜닝 스윕 결과(10장), 기하 후처리(11장)가 정리되어 있다.
2. `README.md`로 실행 방법과 산출물 네이밍 규칙을 확인한다.
3. Phase 표(PLAN 7장)로 현재 진행 상황을 확인하고, 작업 완료 시 해당 행을 갱신한다.

## 작업 규칙

- Zivid API 이름을 추측해서 만들지 않는다. 불확실하면 `zivid-python-samples`를 확인하거나 사용자에게 묻는다.
- 세그멘테이션 방법(m1/m2, m3는 Phase 4)은 반드시 `methods/base.py`의 `Segmenter` 인터페이스를 공유한다. 한 방법의 구현이 다른 방법의 코드에 침범하지 않게 한다.
- 기하 판정(높이, 기울기)은 **카메라 좌표계가 아니라 빈 좌표계(bin frame)** 에서 수행한다. 카메라가 기울여 설치돼 있어 카메라 Z를 높이로 쓰면 빈 한쪽이 통째로 "높다"고 오판된다. 근거는 `PLAN.md` 4장.
  - 단, **마스크 병합의 법선 각도차는 상대량**이라 좌표계와 무관하다. `tilt`(절대량)와 혼동하지 않는다.
- 하드코딩 금지. 임계값은 전부 `config/*.yaml`로 뺀다.
- 주석과 문서는 한국어, 코드 식별자와 API 이름은 영어.

## 측정·비교 규칙

이 프로젝트는 방법 비교 벤치마크가 목적이라 측정 방식 자체가 결과를 좌우한다.

- **타이밍은 warm 기준**이다. `Segmenter.build()`(모델 로드)를 `predict()`에서 분리하고, cold 1회를 버린 뒤 재측정한다.
- **방법 하나만 로드한 독립 프로세스에서 측정한다.** m1·m2를 한 프로세스에 함께 올리면 8GB VRAM 압박으로 warm이 최대 2배까지 부풀었다(`PLAN.md` 11장).
- 난수를 쓰는 피팅을 세그멘테이션 경로에 넣지 않는다. 벤치마크 결과가 실행마다 흔들린다. 마스크 평면 피팅은 트리밍 PCA(결정적)를 쓴다.
- `bin_frame_*.json`은 RANSAC(난수) 산출물이다. **기존 결과와 비교할 때 `build_bin_frame.py`를 다시 돌리지 않는다** — 높이·최상층·기울기가 전부 미세하게 바뀐다.
- 후보 수가 많은 것이 곧 품질이 아니다. 정답 라벨이 없는 상태에서 기각 임계를 임의로 정하지 않는다(현재 전부 `null`).
